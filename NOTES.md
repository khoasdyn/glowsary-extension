# Notes and open mismatches

This file is the running log of mismatches and open gaps across the project: between the UI and the design, between Figma and the code tokens, between a request and PRD.md, between PRD.md and DESIGN.md, and anything else that does not line up yet. Claude records items here so nothing is lost while a decision is pending. Each item stays until it is resolved, then it is marked done or removed.

How to read an item: the area it touches, what the mismatch or gap is, and its status. Open means it still needs a decision or a fix. Resolved means it is settled.

## Open

8. Icon Button sizing has no tokens. The Icon Button is a fixed 40 by 40 box with an 18 by 18 icon, both temporary raw values in the Icon Button spec, because no spacing or sizing scale exists yet. Same debt as the Text Button (item 1) and the Switch (item 6). Area: DESIGN.md and code tokens. Status: open, debt; swap for tokens once the scale lands.
9. Icon Button has no interaction states. Figma defines only the three static variants (Primary, Secondary, Destructive). There is no hover, focus, pressed, or disabled state. Same gap as the Text Button (item 2) and the Switch (item 5). Area: Figma and UI. Status: open, waiting on the user to design these states in Figma.
10. Icon Button needs an accessible name and a tooltip. The button is icon-only with no visible text, so each use must pass an accessible name for screen readers and a tooltip for sighted users. Figma does not specify these. Area: UX and build. Status: open, handled as a build requirement in the plan; revisit if Figma later defines tooltip text.
11. Variant naming is inconsistent between Text Button and Icon Button. The Text Button calls its solid dark variant "Default"; the Icon Button calls the same role "Primary". This is a design-system naming gap that may confuse readers. Area: Figma and DESIGN.md. Status: open, waiting on the user to pick one name across both components in Figma.
13. The name "Icon Button" collides with an existing `icon-button` CSS class. The code already uses an `icon-button` class for the form modal's text "×" close button, which is a different thing from the new Icon Button component. When Codex builds the component, the naming must be sorted so the two do not clash, and it should be decided whether that close button later becomes a real Icon Button instance. Area: DESIGN.md and code. Status: open, to handle when the component is built and applied.
12. Icon Button and Text Button treat "Destructive" differently. The Icon Button's Destructive is a solid red circle (`--bg-error-solid` with `--fg-error-white`), while the Text Button's Destructive has no fill and shows plain red text (item 3). For a delete action the Icon Button reads much stronger. This may be intended or may need aligning once the Destructive look is decided. Area: Figma and UX. Status: open, linked to item 3; waiting on a design decision from the user.

5. Switch has no disabled, hover, pressed, or focus state in Figma. Figma defines only off and on. For accessibility the switch keeps a visible keyboard focus indicator until Figma defines a focus style. Area: Figma and UX. Status: open, waiting on a design decision from the user.
6. Switch sizing and spacing have no tokens. The track (54 by 28), padding (4 top and bottom, 6 left and right), and the knob (20 by 20) are temporary raw values in the Switch spec, because no spacing or sizing scale exists yet. Same debt as the Text Button (item 1). Area: DESIGN.md and code tokens. Status: open, debt; swap for tokens once the scale lands.

## Resolved

20. The header did not match the Figma Page Nav mockup. The implementation showed "Glowsary" with a subtitle, left-aligned, while the Figma "Page Nav" frame (node 20:1601) showed a single centered title "Welcome to Glowsary!" with no subtitle above the tab nav. The user chose to match the Figma mockup (decision 2026-06-08). PRD.md FR-38, the Shared header entry, and the Management view entry were updated to the centered "Welcome to Glowsary!" title with no subtitle, and a build plan was issued to change the implementation. Area: Figma versus PRD.md and the implementation. Status: resolved 2026-06-08; implementation change handed to build mode.

16. The shared header subtitle reading slightly off on the Settings tab is now moot. The subtitle was removed entirely when the header changed to match the Figma mockup (see item 20), so it no longer shows on either tab. Area: UX and copy. Status: resolved 2026-06-08.

15. The Tab nav component was not specced. The redesign needs a Home/Settings tab nav, which was new: no DESIGN.md entry and not in the code. It is now specced in the DESIGN.md Components section as "Tab nav", built from the Figma tab nav frame, and the corner radius scale wording was reconciled from "the tab bar" to "the Tab nav". All colors map to existing tokens (`--bg-tertiary` track, `--bg-primary` active item, `--text-primary` label, `--fg-primary` icon) and both icons already ship in `extension/assets`. Open debt from this component is tracked separately in items 17 and 18. Area: DESIGN.md and code. Status: resolved 2026-06-08.

14. The management view two-tab split was not in PRD.md. The management view was defined as one page holding all pieces together. PRD.md now defines the two-tab layout: a shared header above a tab nav, Home as the default tab with the highlighting bar, Add new, and the saved words area, and Settings with the excluded sites manager (FR-38 to FR-41, and the updated component entries). Also renamed the "settings bar" to the "highlighting bar" to avoid confusion with the Settings tab (decision 2026-06-08). Area: request versus PRD.md. Status: resolved 2026-06-08.
